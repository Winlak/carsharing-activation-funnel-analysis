# Data dictionary

## Источник и статус данных

Источник — детерминированный генератор [`scripts/generate_data.py`](../scripts/generate_data.py), seed `20250812`. Это воспроизводимые **синтетические** данные: они не получены от Делимобиля, любого другого оператора или из персональных данных. Для исходных данных не требуется внешняя лицензия; код проекта доступен по [MIT-лицензии](../LICENSE).

Генератор создаёт регистрации с 1 января по 30 апреля 2025 года и события до 30 июня 2025 года. Все timestamp в UTC. Полный `data/raw/events.csv` создаётся локально и исключён из Git; в репозитории остаётся лишь 120-строчный [sample](../data/sample/events_sample.csv).

## `data/raw/events.csv`

Гранулярность: одна строка — одно событие пользователя. Идентификаторы синтетические; PII и платежных реквизитов нет.

| Поле | Тип | Описание | Правило/пример |
|---|---|---|---|
| `event_id` | string | Детерминированный ID события | Уникален; SHA-256-derived, 24 символа |
| `user_id` | string | Синтетический ID пользователя | `u_00001`; не является реальным идентификатором |
| `event_name` | string | Название события | Один из `signup`, `verification`, `payment_method`, `search`, `booking`, `first_ride`, `ride_completed` |
| `event_ts` | ISO 8601 UTC | Время события | Например, `2025-01-01T00:12:10Z` |
| `session_id` | string | Синтетический ID сессии/шага | Используется для реалистичности event log, не для расчёта воронки |
| `acquisition_channel` | enum | Канал привлечения | `organic`, `paid_search`, `referral`, `partner` |
| `platform` | enum | Платформа на момент регистрации | `ios`, `android`, `web` |
| `city` | enum | Город регистрации | `Moscow`, `Saint Petersburg`, `Kazan` |

### Семантика событий

| Событие | Значение в кейсе | Место в расчёте |
|---|---|---|
| `signup` | Пользователь завершил регистрацию | Основание когорты и начало воронки |
| `verification` | Пользователь завершил идентификацию | Второй шаг |
| `payment_method` | Привязан хотя бы один способ оплаты | Третий шаг |
| `search` | Выполнен поиск автомобиля | Четвёртый шаг |
| `booking` | Создано бронирование | Пятый шаг |
| `first_ride` | Завершена первая поездка | Активация и шестой шаг |
| `ride_completed` | Завершена последующая поездка | Retention после первой поездки |

## `data/raw/users.csv`

Гранулярность: одна строка — один зарегистрированный синтетический пользователь. Поля: `user_id`, `signup_ts`, `acquisition_channel`, `platform`, `city`. Это удобная dimension-таблица; в базовом SQL сегменты берутся из event log и проверяются на согласованность в генераторе.

## Производные таблицы

| Файл | Гранулярность | Назначение |
|---|---|---|
| `data/processed/data_quality.csv` | правило проверки | Число нарушений данных |
| `data/processed/funnel_overall.csv` | шаг | Общая воронка и drop-off |
| `data/processed/funnel_by_segment.csv` | сегмент × шаг | Воронки по каналу, платформе и городу |
| `data/processed/time_to_step.csv` | переход | P50/P90 часов между соседними шагами |
| `data/processed/cohorts.csv` | месяц регистрации | Activation и retention D1/D7/D30 |

## Допущения генератора

Генератор задаёт вероятности переходов до наступления результата. В частности, он создаёт более слабые переходы в web и Saint Petersburg на отдельных этапах, чтобы кейс содержал реалистичные диагностические разрезы. Поэтому наблюдаемые различия — свойство тестовых данных, а не доказательство реального поведения пользователей.
