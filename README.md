# Воронка первой поездки в каршеринге

[![CI](https://github.com/Winlak/carsharing-activation-funnel-analysis/actions/workflows/ci.yml/badge.svg)](https://github.com/Winlak/carsharing-activation-funnel-analysis/actions/workflows/ci.yml)

Анализ пути от регистрации до первой поездки. Считаю конверсию на каждом шаге, время переходов и различия между группами пользователей.

> Важно: это **синтетические, детерминированно сгенерированные данные**. Они не являются данными Делимобиля или другого каршеринга, не содержат PII и не используются для утверждений о рынке.

## Короткий ответ

За 12 000 синтетических регистраций первой поездки достигли 3 068 пользователей — **25,6%**.

- **Наибольшая абсолютная потеря — регистрация → верификация:** 2 930 пользователей. **Худшая конверсия перехода — поиск → бронирование:** 63,7%, или 2 240 потерянных пользователей. Это разные критерии; приоритет требует оценки причин, ожидаемого эффекта и стоимости изменений.
- **Оплата — отдельная точка диагностики:** verification → payment_method конвертирует 73,9%. На web — 60,2% против 78,4% на iOS; это факт сегментного различия в симуляции, а не доказательство причины.
- **Web и Saint Petersburg — диагностические срезы:** итоговая конверсия web — 12,5%, iOS — 29,9%; search → booking в Saint Petersburg — 56,8% против 66,0% в Moscow. Для объяснения нужны события доступности, цены и ошибок, которых в текущем логе нет.

Подробный разбор с графиками, когортами и планом экспериментов: [аналитический отчёт](reports/analysis_report.md). Проверка методологии и расчётов: [validation report](reports/validation_report.md).

## Методика в двух словах

- **Период регистрации:** 1 января — 30 апреля 2025; дата среза событий — 30 июня 2025, UTC.
- Часовой пояс сессии DuckDB явно установлен в UTC: месячные когорты не зависят от настроек компьютера. Численность когорт сверяется в тесте с независимой группировкой событий в pandas.
- **Единица анализа:** `user_id`. На шаге учитывается первое валидное событие пользователя, поэтому повторы не раздувают воронку.
- **Последовательность:** `signup → verification → payment_method → search → booking → first_ride`. Следующий шаг засчитывается только после предыдущего.
- **Окно конверсии:** 30 суток после регистрации; все когорты имеют полное D30-окно.
- **Cohorts:** activation D1/D7/D30 — первая поездка в пределах N суток от регистрации. Retention D1/D7/D30 — следующая завершённая поездка в [D, D+1) суток от первой; знаменатель — только активированные пользователи с завершённым окном наблюдения.

Полные определения и защита от right-censoring — в [методике](docs/methodology.md); схема данных — в [data dictionary](docs/data_dictionary.md).

## Воспроизводимость

Требуется Python 3.9+.

```bash
git clone https://github.com/Winlak/carsharing-activation-funnel-analysis.git
cd carsharing-activation-funnel-analysis
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
make all
```

Полезные команды:

```bash
make lint   # ruff
make test   # ключевые проверки генератора и метрик
make check  # lint + test + полный pipeline
make clean  # удалить только воспроизводимые raw/intermediate артефакты
```

`make all` генерирует полный `data/raw/events.csv` локально; он намеренно не хранится в Git. Seed `20250812` обеспечивает повторяемость. Маленький sample и все итоговые отчёты/графики доступны в репозитории.

## Качество, ограничения и следующие шаги

Пайплайн проверяет уникальность ID, обязательные поля, разрешённые event names, выход за дату среза и нарушенный порядок шагов. В текущем прогоне все пять SQL-проверок вернули 0 нарушений; pytest проверяет также детерминированность, зависимости шагов, монотонность воронки и D1 ≤ D7 ≤ D30.

Сегментные результаты описательны. Генератор намеренно создаёт различия, а в лог не заложены цена, количество доступных авто, ETA, ошибки/3DS, отмены или experiment assignment. Поэтому в отчёте чётко отделены **факты симуляции** от **гипотез** и указан план A/B-проверок с primary metric, guardrails и нужной инструментализацией.
